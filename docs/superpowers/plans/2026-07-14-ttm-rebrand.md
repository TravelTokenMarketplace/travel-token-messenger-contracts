# Travel Token Messenger Rebrand Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rename everything "Camino Messenger" / `CM*` / `cmp.*` in this repo to "Travel Token Messenger" / `TTM*` / `ttm.*`, remove all Camino-network infrastructure, and land the result on a new GitHub repo, ready for a fresh Base Sepolia deployment.

**Architecture:** A single case-aware rename script (kept in the session scratchpad, never committed) is applied path-by-path across five phased commits on the `rebranding` branch — contracts, tests+tooling, UI, docs+config, go bindings — each phase gated by its own build/test command. Storage-namespace constants (ERC-7201) are replaced with pre-computed values. Spec: `docs/superpowers/specs/2026-07-14-ttm-rebrand-design.md`.

**Tech Stack:** Hardhat + Solidity 0.8.24, Hardhat Ignition, React/Vite UI (`ui/`), abigen go bindings (`go/contracts`), `gh` CLI.

## Global Constraints

- Brand: "Travel Token Messenger"; PascalCase `TravelTokenMessenger`; identifier prefix `TTM`/`ttm`; service namespace `ttm.` (from spec).
- New repo: `TravelTokenMarketplace/travel-token-messenger-contracts` (public, default branch `dev`). Old repo stays as remote `old`.
- Never edit `docs/superpowers/specs/*` or `docs/superpowers/plans/*` — historical records.
- Never hand-edit `abi/` (regenerate with `yarn hardhat export-abi`) or `ui/src/contracts/generated/` (git-ignored, regenerated by `yarn sync`).
- Fresh deployment follows later — role hashes, event signatures, EIP-712 domain (`CaminoMessenger` → `TravelTokenMessenger`), and ERC-7201 storage locations may all change, but storage-location constants MUST match their new namespace strings (values pre-computed in Task 2).
- Every commit message ends with `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`.
- All root commands run from the repo root; UI commands run from `ui/`.

## Contracts

- **`TTMAccountManager`** — factory + registry + role management. Creates
  `ERC1967Proxy` instances of `TTMAccount` and tracks the canonical
  implementation, booking token address, developer fee, and the service
  registry (services are referenced by `ttm.services.<package>.<version>.<Name>`).
- **`TTMAccount`** — a Travel Token Messenger account: manages funds,
  messenger bots, supported/wanted services, payment tokens, public keys,
  gas-money withdrawals, and minting/buying of Booking Tokens.
- **`BookingToken`** — ERC-721 representing bookings, with cancellation
  flows and an operator library.

Contracts are UUPS upgradeable (OpenZeppelin upgradeable contracts).
Generated API documentation lives in [`docs/`](docs/index.md).

## Management UI

A wallet-connected management UI for these contracts lives in
[`ui/`](ui/) — see its README/CLAUDE docs for commands.
